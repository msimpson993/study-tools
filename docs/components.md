Running example UI: each running example is introduced by its Example node on the map (no separate fold when refs exist); every node popup shows two callouts ("Adds to the running example", "Lets us account for"); every dive opens with the same box.

**Example-order guard** (`exampleguard.ts`): `exampleLeaks(map, {id, at, words, numbers?, figureIds?, weak?, ignore?})` walks every path from the root along the main lines (side paths too; dashed cross-links are scanned from either end, not walked) and reports each box (label, detail, body, rough, figure id/alt/caption, figure caption, strip row) or line (label, question, idea, why, figures) passed before the host that names the example, tagged main path or side-path only (a side line leaving a reached box counts where it leaves; a reversed look-back only at the box that looks back); `weak` words count only beside a strong one, `boxExtra` adds texts such as quiz items; `formatLeaks` prints them. Used by the apps' unit tests.

Adding a shared feature: put it in `packages/core`, export from `index.ts`, add a unit test (pure parts) and a Playwright check, and document it here.


## Copy reference

A small copy-icon button (`copyRefButton` in `copyref.ts`, accessible name *Copy reference to this*) sits in the header of every map node or edge panel, deep dive, live figure (inline and expanded) and quiz question. It copies a compact plain-text packet to the clipboard — page title, the path of questions from the central question, what is being viewed, a `#/node/<id>` (or dive / figure / quiz) deep link, a trimmed short answer, and for figures the current control values — so Malcolm can paste it into a subject-tutor chat before asking a question. Nothing is sent anywhere; if `navigator.clipboard` is missing (for example `file://`) the button falls back to `document.execCommand('copy')` or a selectable dialog. Brief **Copied** feedback appears on the button. Opening `#/node/<id>` or `#/edge/<from>__<to>` selects that box or line on the map (the address bar is kept in sync with `replaceState` while you browse). Test ids: `copy-ref`. Unit tests: `packages/core/test/copyref.test.ts`. Playwright: `tests/e2e/copyref.spec.ts`.

## How to add a visual to a dive (the 3-step recipe)

1. Describe the figure in `content/figures.yaml`: `title`, axes (`x`, `y` with units), `legend`, `howToRead`, `lookFor` (one sentence on what to notice), `controls`, `presets` (each preset only sets visible controls), and `animate: { control, speed }` when a moving picture helps (the control's own slider is the scrubber; reduced-motion users get a Step button).
2. Draw it: `figs.ts` exports `figureOf((controls) => [panel, panel])`; register it in `main.ts` under `figures: { <id>: … }`.
3. Place it in the dive with a ```` ```figure:<id> ```` fence after a one-line "Picture it first." lead-in. The build fails if the id does not exist; `tests/e2e/visuals.spec.ts` checks that it draws, reacts to a control, animates and fits at 390 px.
