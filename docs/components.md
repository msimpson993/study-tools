# Components (`packages/core`)

All vanilla TypeScript/DOM, no framework. Import from `@study/core` (UI) and `@study/core/dsp` (math). Styles come with `initTheme()`.

| Module | What it is | Notes |
|---|---|---|
| `theme.ts`, `styles/theme.css`, `core.css` | True-black dark default, light toggle, persisted (`study-theme`). | CSS variables: `--bg --panel --text --muted --accent --cyan --org --grn --vio …`. Shared class names are prefixed `st-` (`st-seg`, `st-eq`, `st-ctl`, …) so legacy page CSS cannot collide. |
| `app.ts` `mountApp(content, hooks)` | Page shell: top bar (☰, Variables, Hub, theme), collapsible sidebar, hash router, dive view, glossary drawer. | `hooks.figures[id]` mounts a figure; `hooks.board(host, params)` lazily mounts one custom board view. The board route starts with the sidebar tucked away. |
| `conceptmap.ts` `mountConceptMap` | The map. Auto layout (staggered rows, orthogonal edge tracks, collision-avoided pill labels), every box/line/dot tappable → popup, box tap = path-to-root highlight, line tap = that line + its two end boxes only (`mapHighlight`), one-row legend (`map-legend`: solid = next question, dashed = same idea in another view, hexagon = fork, pill = start, and one coloured chip per chapter named by `seriesNames` — tap a chip to light that chapter's boxes; lists only what the current map uses, one shared dash pattern `--qm-dash`), Explore/Review modes, Recall (hide text), quiz this box / branch / missed. | Geometry lives in `maplayout.ts` (pure, unit-tested; `overlapReport`). Build side (`packages/build`): `loadApp` (validate + render Markdown/KaTeX), `contentPlugin` (virtual modules `virtual:study-content`, `virtual:katex-css`), `appConfig` (single-file Vite config).

Running example UI: the map shows a collapsed "Running example: …" fold; every node popup shows two callouts ("Adds to the running example", "Lets us account for"); every dive opens with the same box.

Adding a shared feature: put it in `packages/core`, export from `index.ts`, add a unit test (pure parts) and a Playwright check, and document it here.

## How to add a visual to a dive (the 3-step recipe)

1. Describe the figure in `content/figures.yaml`: `title`, axes (`x`, `y` with units), `legend`, `howToRead`, `lookFor` (one sentence on what to notice), `controls`, `presets` (each preset only sets visible controls), and `animate: { control, speed }` when a moving picture helps (the control's own slider is the scrubber; reduced-motion users get a Step button).
2. Draw it: `figs.ts` exports `figureOf((controls) => [panel, panel])`; register it in `main.ts` under `figures: { <id>: … }`.
3. Place it in the dive with a ```` ```figure:<id> ```` fence after a one-line "Picture it first." lead-in. The build fails if the id does not exist; `tests/e2e/visuals.spec.ts` checks that it draws, reacts to a control, animates and fits at 390 px.
